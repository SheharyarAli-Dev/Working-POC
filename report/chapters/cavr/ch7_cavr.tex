\section{CAVR Testing}\label{sec:cavr-testing}
\begin{sloppypar}
CAVR is tested at four levels. Unit tests cover each stage on its own (capture, gate, PyPI client, wheel metadata, tree, advisories, scan, contract, sink judgement, cache). Pipeline tests run \path{verify_request} end to end with a local transport that serves real file bytes, including the real \texttt{pypdf-6.19.0} wheel of 395\,480 bytes, and a registry answer whose digest is computed from those bytes. Interface tests cover the pip wrapper, the dashboard API over HTTP, and the page components rendered to HTML with Node.js. Seven live tests run against the real PyPI and OSV and are skipped unless \texttt{CAVR\_LIVE=1} is set. The advisory tests use two real OSV answers recorded on 2026-10-10: 97 advisories for pypdf 5.1.0 and the empty answer for pypdf 6.19.0. Synthetic advisories are used only for range shapes the real data lacks and are labelled \texttt{SYNTH-n}.
\end{sloppypar}

\begin{sloppypar}
Each plan step was also checked by fault injection: one line of the new code was changed at a time, the tests were run, and the file was restored. A fault that no test caught led to a new test. The working notes record 24 faults for the pipeline step (11 in \path{reachability.py}, 13 in \path{pipeline.py}), 16 for the fix that followed its review, 17 for \path{pip_shim.py} and 20 for the dashboard API (17 in \path{api.py}, 3 in \path{assurance.py}).
\end{sloppypar}

The other refusal cases the tests cover, by group:
\begin{itemize}
    \item \textbf{Input the capture cannot model:} a requirements file that includes itself, a file that is not UTF-8, a file outside the project directory, credentials inside a URL.
    \item \textbf{Policy and lockfile:} a policy that is not valid JSON, an allowlist entry that looks right inside an invalid policy, a forged \texttt{pinned} flag in the record, a malformed capture record.
    \item \textbf{Registry answers:} a release the registry does not have, a yanked release, a release with only a source distribution, an answer naming another package, a file URL on another host, a download slower than the deadline.
    \item \textbf{Hostile archives:} zip bomb, too many entries, an entry that escapes the install directory, a symlink entry, two entries that differ only in case or Unicode form, metadata that names another package.
    \item \textbf{Tree:} dependency cycle, two lockfile versions that both fit, a wheel that needs a newer Python.
    \item \textbf{Code the scan cannot read:} syntax error, native extension, bytecode-only file, executable \texttt{.pth} file, a source file over the size budget.
    \item \textbf{Contract and sinks:} a package imported and never used, a star import, a reader created outside the guard, pages read after the guard block has ended.
    \item \textbf{Cache:} a row copied under another key, an incomplete key, a verdict that is not cacheable.
    \item \textbf{Dashboard:} a fault inside the pipeline, a run under a demo condition, a verdict with no evidence at all.
\end{itemize}

\subsection{Deferred Work}
These items are known, written down, and not done in this iteration.
\begin{sloppypar}
\begin{itemize}
    \item \textbf{Docker sandbox in CI.} The sandbox image has not been built and the container command has not been run. The CI job with a real Docker sandbox is deferred, so the tests cover the no-container mode only.
    \item \textbf{Sandbox execution on real packages.} Counterfactual activation, OS-level observation, the causal graph, repair and re-verification are not part of the fast gate. A request that needs them ends \texttt{UNRESOLVED} with the escalation text.
    \item \textbf{strace parser.} A refused or blocked connect and a failed open of a secret file still leave no event, and an \texttt{EINPROGRESS} connect is recorded without checking that it completed.
    \item \textbf{Forged sandbox report.} A package that prints one forged report and suppresses the real one is not detected. That needs a report channel the package cannot write to.
    \item \textbf{Orchestrator path.} The shared orchestrator still calls the older analyzer in \path{backend/cavr/analyzer.py} and not \path{verify_request}. The change was stopped for a decision, because it turns the orchestrator's safe scenario into \texttt{UNRESOLVED} when no OSV answer is stored.
    \item \textbf{Browser test of the page.} The page components are rendered and checked in tests, but the click handlers and the live event stream have no automated test.
    \item \textbf{Cache integrity.} The row digest is a plain SHA-256; a keyed digest is deferred.
    \item \textbf{Evaluation.} Measuring detection and false-positive rates on a package corpus, and setting a latency target, belong to the later evaluation work.
\end{itemize}
\end{sloppypar}
