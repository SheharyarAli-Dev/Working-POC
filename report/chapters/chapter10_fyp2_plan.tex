\section{CAVR Continuation: Proposed Research Work}
The CAVR design identifies the following research questions and evaluation directions. They are proposed work, not completed FYP-2 results or an approved team schedule.
\begin{enumerate}
    \item Evaluate whether task and repository context can infer a minimum capability contract with acceptable false positives, including benign security-sensitive package behavior.
    \item Under a fixed exploration budget, compare security-targeted counterfactual environment synthesis with a single normal sandbox run for activation of hidden behavior.
    \item Compare the proposed approach with registry metadata checks, OSV, static-only analysis, a normal dynamic sandbox, and reproducible research detectors; use component ablations to measure the contribution of capability contracts, counterfactual activation, causal graphs, repair, and clean reconstruction.
    \item Evaluate minimal compatible repair and fresh-state re-verification for preservation of used functionality, and report detection, false-positive, repair, and assurance limits on controlled scenarios.
\end{enumerate}

\section{SATRA-RV Continuation: Proposed Research Work}
The SATRA-RV design defines independent benchmark ground truth and mandatory stress cases. The following are proposed evaluation directions, not completed FYP-2 results or an approved team schedule.
\begin{enumerate}
    \item Define each security obligation and expected outcome independently of SATRA-RV, and validate candidate security mutants with a separate policy oracle or reviewer before evaluation.
    \item Evaluate the four core combinations of application state (unchanged or regressed) and security-test state (trusted or weakened), including legitimate secure refactors and the design's additional adversarial test changes.
    \item Compare the combined gate with trusted tests, test-integrity heuristics, and mutation-based evidence; report when a case is preserved, weakened, regressed, inconclusive, or invalid under the defined labels.
    \item Measure the bounded benchmark outcomes and reproducibility, retaining invalid or inconclusive cases in the report rather than treating them as successful detections.
\end{enumerate}

\section{Remaining Scope}
The Integrated Design v1.0 defines ASENT's bounded project scope \cite{asentIntegratedResearchDesign}. CAVR addresses direct and transitive Python/PyPI and JavaScript/npm dependencies on Linux. SATRA-RV addresses Python web applications and bounded security families, including authentication/authorization and IDOR, injection, path traversal, XSS, SSRF, CSRF, and insecure deserialization. SABLE addresses Terraform/HCL refactoring and continuity of AWS S3/IAM least-privilege role-to-asset bindings. The shared system operates on a candidate workspace with bounded retries and escalates uncertain outcomes.

The design does not claim universal coverage of agents, languages, frameworks, AWS services, clouds, or arbitrary Terraform equivalence; perfect malware proof; or that uncertainty is safe. Remaining work and evaluation stay within these boundaries. Scope expansion requires evidence and review under the FYP-2 research plan.

\section{Remaining Modules and Shared Features}
The integrated design proposes continued work across all three modules and the shared gate. CAVR's remaining research includes capability-contract quality, counterfactual activation, causal behavior analysis, minimal compatible repair, and re-verification. SATRA-RV's includes independent benchmark ground truth, validated adaptive tests, repair acceptance, differential verification, and baseline/kill-test evaluation. SABLE's includes bounded obligation projection, successor attribution, baseline comparison, uncertainty evaluation, and reproducibility. Shared work includes the RunContext, candidate workspace, routing, evidence schema/bus, cross-module invalidation, combined gate, integrated benchmark, and evidence report \cite{asentIntegratedResearchDesign}.

\section{Remaining Iterations}
The integrated design organizes the remaining year into six parallel two-month work periods, with outputs for CAVR, SATRA-RV, SABLE, and shared integration in each period. The detailed module and shared milestones are listed in Section~\ref{sec:asent-timeline}. This is a relative research roadmap, not a sequence in which one module is completed before another or a dated sprint commitment \cite{asentIntegratedResearchDesign}.

\section{Implementation Plan}
Implementation follows parallel module lanes with shared integration milestones. The proposed shared architecture comprises a local orchestrator, candidate workspace, routing, evidence bus, input/hash binding, invalidation, and final gate. Each module's research result remains separate evidence; the gate combines applicable module decisions for the same candidate snapshot. The design calls for scope expansion only when evaluation evidence justifies it. The integrated plan is a proposed design roadmap; this report does not claim approved owners or calendar dates.

\section{Testing and Validation Plan}
Benchmark obligations and expected outcomes are established independently of the module under evaluation. The proposed validation records module-specific baselines, ablations, kill tests, failures, inconclusive cases, and environment limitations. CAVR metrics include precision/recall/F1, dormant-trigger activation, new sensitive paths per counterfactual run, false positives, p50/p95 analysis time, deep-escalation and cache rates, cross-package attribution, repair success/minimality, functional preservation, and assurance completeness. SATRA-RV metrics include security detection recall, false-block rate, dynamic-test acceptance/discrimination, repair success and induced regression, silent-regression catch rate, repair iterations, local overhead, Ollama calls/tokens, and evidence completeness. SABLE metrics include false-safe rate, regression recall, false-regression rate, successor-correspondence accuracy, UNKNOWN precision, evidence completeness, and analysis overhead. Integrated scenarios measure end-to-end false-safe acceptance, unnecessary block/review, developer wait time, cross-module invalidation/re-run cost, combined evidence completeness, and success on a candidate exercising all applicable modules. These are proposed measures from the integrated design, not results already obtained \cite{asentIntegratedResearchDesign}.

\section{Deployment Plan}
The design defines a local, Linux-based prototype using open-source components; it does not specify a hosted production deployment or a live-cloud rollout. Demonstrations and evaluation use local fixtures and controlled environments. SABLE is pre-deployment analysis: the reported scope does not apply Terraform or contact AWS. A later live-cloud deployment or evaluation would require a separately approved environment and safety scope; it is not part of the defined plan.

\section{Tentative Timeline}\label{sec:asent-timeline}
The Integrated Design v1.0 gives the following relative 12-month plan \cite{asentIntegratedResearchDesign}. The source does not provide calendar start dates, and this report does not convert the relative months into dates.
\begin{enumerate}
    \item \textbf{Months 1--2:} CAVR interception, context, artifact resolution, and fast risk/cache design; SATRA-RV repository capture, security localization, and Security Change Contract; SABLE scope freeze, HCL normalization, obligation schema, and benchmark seed. Shared milestone: freeze common context, candidate workspace, router, evidence schema, and POC requirements.
    \item \textbf{Months 3--4:} CAVR capability inference, trigger extraction, and first sandbox; SATRA-RV security dictionary, deterministic harness, and static adapters; SABLE resource graph, successor correspondence, and policy semantics. Shared milestone: first three-lane prototype with shared hashes and module-status API.
    \item \textbf{Months 5--6:} CAVR counterfactual scheduling, event normalization, and canary flow; SATRA-RV validated dynamic-test generation and finding correlation; SABLE obligation projection, attribution, and UNKNOWN handling. Shared milestone: parallel execution, evidence bus, and first integrated POC run.
    \item \textbf{Months 7--8:} CAVR causal graph, policy decision, and analysis-budget tuning; SATRA-RV bounded repair and differential sandbox; SABLE evaluation/failure analysis and handoff. Shared milestone: cross-module invalidation and combined gate v1.
    \item \textbf{Months 9--10:} CAVR constraint and transitive-path repair with re-verification; SATRA-RV decision/evidence/recommit layer, stress cases, and baselines; SABLE support for integrated hard cases without evidence-free scope expansion. Shared milestone: performance work and module re-run minimization.
    \item \textbf{Months 11--12:} CAVR clean reconstruction and assurance certificate; SATRA-RV final baseline/kill-test evaluation and hardening; SABLE reproducibility and integrated scenarios. Shared milestone: integrated benchmark, combined POC, final evidence report, thesis, and defense package.
\end{enumerate}

\section{Expected Final Deliverables}
The integrated design lists a local ASENT orchestrator and final gate; functional CAVR, SATRA-RV, and SABLE engines; an integrated dashboard reflecting backend state; a controlled benchmark with module-specific baselines, ablations, and kill-test results; a combined assurance report bound to the accepted snapshot; and an integrated POC demonstrating blocking, correction, and clean acceptance across applicable modules \cite{asentIntegratedResearchDesign}. These are expected FYP deliverables, not claims that they are all complete at mid-evaluation.
