# Phase 7 walkthrough: Ollama Live LLM Integration & 7-Check Test Validator

Files: `backend/satra/ollama_adapter.py`, `backend/satra/test_validator.py`, `tests/test_satra_ollama_and_validator.py`.

## Ollama Live LLM Adapter

Connects to the local Ollama instance running `qwen2.5-coder:1.5b` with full streaming, strict JSON formatting, and SHA-256 prompt fingerprinting.

| Capability | Implementation | Purpose |
|---|---|---|
| Auto-Discovery | `pick_ollama_endpoint()` in `settings.py` | Detects WSL host gateway (`172.27.0.1:11434`) or localhost |
| Streaming Generator | `generate_completion_stream()` | Streams tokens directly for interactive progress |
| Structured JSON | `generate_structured()` | Forces model output into verifiable JSON schema |
| Prompt Fingerprinting | `prompt_fingerprint` (SHA-256) | Non-repudiation and replay verification |
| Latency Tracking | `latency_ms` | Accurately records local inference runtime |

## 7-Check Test Validator Pipeline

Every test candidate generated by an LLM or proposed by a developer is subjected to an unskippable 7-gate validation pipeline (`validate_generated_test`):

1. **Check 1: Syntax & Vocabulary Preflight** (`ast.parse`, only allowed imports like `pytest`, no dangerous calls `eval`, `exec`, `open`, `__import__`).
2. **Check 2: Assertion Presence** (verifies that non-vacuous assertions exist; bare calls without assertions fail).
3. **Check 3: Assertion Integrity & Tampering** (detects weakened status code allowances e.g. `in [200, 403]`, trivial `assert True`).
4. **Check 4: Contract Alignment** (verifies rule ID and expected HTTP status e.g. `403` match the security contract).
5. **Check 5: Secure Baseline Pass** (the test MUST pass cleanly on the uncompromised baseline).
6. **Check 6: Counterfactual Mutant Kill** (the test MUST fail / kill the AST counterfactual mutant).
7. **Check 7: Baseline Repeatability** (the test execution is repeated to guarantee determinism without flakiness).
